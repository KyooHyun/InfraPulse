# FDS 성능 평가 — 재측정 예정

## 이전 결과 철회

이 디렉터리에는 ULB Credit Card Fraud 데이터셋(n=284,807, fraud=492)으로 "룰 단독 vs
룰+Isolation Forest 앙상블"을 비교해 **FPR ▼50%, Recall ▼0.41%p**라고 적은 결과가 있었다.
이 수치는 철회했다. 이유:

1. **기준선이 실제 엔진이 아니었다.** `creditcard_eval.py`의 "룰 단독"은 `app/fds_engine.py`를
   호출하지 않고, `Amount >= p95 → 45점` 룰 하나를 스크립트 안에서 따로 구현했다. 실제 엔진의
   HIGH_VALUE는 30점이라 단독으로는 MEDIUM(40점)에도 못 미친다. 즉 비교 대상이 운영 시스템과
   다른, 평가용으로 만든 기준선이었다.
2. **α가 스크립트마다 달랐다.** `creditcard_eval.py`는 α=0.4, `paysim_eval.py`는 α=0.6이었다.
3. **비교 방식이 주장을 뒷받침하지 못한다.** FPR 절반 감소는 임계값만 올려도 얻을 수 있다.
   앙상블이 낫다고 말하려면 **같은 알림 건수에서의 recall**이나 PR-AUC로 비교해야 한다.
   Recall 8.74%는 사기 492건 중 약 43건을 잡았다는 뜻이기도 하다.

결과 파일(`results.json`)은 삭제했고, `GET /fds/comparison`은 재측정 전까지 `{"status": "pending"}`을 반환한다.

## 재측정 계획

- 벤치마크는 **PaySim 하나**로 통일한다. ULB는 금액 외 피처가 PCA로 익명화되어 있어
  운영 엔진의 룰(잔액·계좌 기반)을 적용할 수 없다.
- 평가 코드는 실제 엔진의 점수 함수를 직접 import하고, α는 설정 한 곳에서만 읽는다.
  평가 스크립트가 엔진 로직을 따로 구현하는 구조 자체를 없앤다.
- 임계값은 앞 구간(step)에서 정하고 뒤 구간에서 평가한다(시간 분할).
- 비교 지표: 동일 알림 예산(예: 상위 0.5%)에서의 recall, PR-AUC.

## 기존 스크립트

`creditcard_eval.py`, `paysim_eval.py`는 재측정 작업에서 교체할 예정이며, 철회 근거를
확인할 수 있도록 그때까지 남겨 둔다.
